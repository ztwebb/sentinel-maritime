# CLAUDE.md — Sentinel Maritime

## Operating Rules

- **Quality gates**: `npm run build` and `npm run lint` must both pass before any work is considered done. There is no test suite yet.
- **Cesium is client-only**: Never import `cesium` at the top level of a server component or layout. Always load CesiumViewer via `next/dynamic` with `{ ssr: false }`. The only file that `import("cesium")` is `components/cesium/CesiumViewer.tsx`, and it does so inside a `useEffect` async IIFE.
- **No paid API keys**: All imagery and data sources must be free-tier (ESRI Dark Gray Canvas, NGA World Port Index). Never add a Cesium Ion token or any key that requires a paid account.
- **Entity ID convention**: Cesium entity IDs follow the pattern `{type}:{id}` (e.g. `vessel:v-001`, `port:p-jebel-ali`, `chokepoint:cp-hormuz`).
- **Zustand subscribe pattern**: Zustand v5 one-argument `subscribe(state => ...)` form with manual `prevValue` comparison. Push every unsubscribe function into a `cleanupFns` array and call them all in the `useEffect` return.
- **`data/ports.json` is machine-generated**: Produced by `node scripts/import-wpi-ports.js` from NGA World Port Index source data. Never hand-edit — regenerate via the script instead.
- **Intelligence console aesthetic**: Dark backgrounds (`#060a10`, `#080f1c`), monospace fonts, uppercase labels (`text-[9px] tracking-[0.15em]`), military/intelligence tone in contextual text. Do not lighten the palette or add rounded corners.

## Commands

```
npm run dev                      # Start Next.js dev server
npm run build                    # Production build (quality gate)
npm run lint                     # ESLint (quality gate)
node scripts/import-wpi-ports.js # Regenerate data/ports.json from NGA WPI
```

## Project Structure

| Path | Purpose | Key Rules |
|---|---|---|
| `app/` | Next.js App Router pages and layout | `layout.tsx` is a **server component** — no Cesium, no `"use client"` unless adding client wrappers. `page.tsx` loads CesiumViewer via `next/dynamic`. |
| `components/cesium/` | Cesium globe rendering | Client-only. Single `CesiumViewer.tsx` owns all entity creation, click handling, and Zustand subscriptions for the globe. |
| `components/layout/` | HUD overlay shell | `HUD.tsx` — `pointer-events-none` wrapper, children opt in with `pointer-events-auto`. |
| `components/ui/` | UI panels and controls | `IntelligencePanel.tsx` (right sidebar detail view), `LayerToggleBar.tsx` (top bar with layer toggles + theater presets). |
| `lib/adapters/` | Data access layer | **Adapter pattern**: `types.ts` defines all entity interfaces; `mock-adapter.ts` reads from JSON. New data sources get a new adapter file exporting the same function signatures. |
| `lib/` | Shared utilities | `theaters.ts` (theater presets), `geo.ts` (haversine). Pure functions, no React imports. |
| `store/` | Zustand state | `useAppStore.ts` — single flat store. All app state lives here (layers, selection, theater). |
| `data/` | Static JSON datasets | `vessels.json`, `ports.json`, `chokepoints.json`. Ports are machine-generated; vessels and chokepoints are curated. |
| `scripts/` | Build/data scripts | `copy-cesium.js` (postinstall — copies Cesium static assets to `public/cesium-static`), `import-wpi-ports.js`. |
| `public/cesium-static/` | Cesium runtime assets | Auto-generated by postinstall. Do not commit or hand-edit. |

## Definition of Done

Before considering any change complete:

- [ ] `npm run build` passes
- [ ] `npm run lint` passes
- [ ] New entity types added to `lib/adapters/types.ts`
- [ ] Cesium imports only inside `components/cesium/` and only via dynamic `import("cesium")`
- [ ] Zustand state uses flat store pattern (no nested reducers, no middleware)
- [ ] No new dependencies added without discussion
- [ ] README updated if the change represents a phase milestone

## Change Discipline

- **Atomic commits**: One logical change per commit.
- **Commit message format**: Match existing history — `Phase X.Y — description` for milestones, plain imperative for smaller fixes.
- **No speculative refactoring**: Only change code that the current task requires.
- **Separate data from UI**: If both `data/*.json` and component files change, prefer separate commits.
- **Preserve color mappings**: The hex values in `CesiumViewer.tsx` (`VESSEL_HEX`, `PORT_HEX`, `CHOKEPOINT_HEX`) and the corresponding Tailwind classes in UI components are deliberately matched. Changing one requires updating the other.

## Architecture Constraints

- **Single-page app**: One route (`/`). The globe + HUD is the entire UI.
- **No SSR for Cesium**: Cesium requires browser APIs (WebGL, DOM). Always `next/dynamic` with `ssr: false`.
- **Adapter pattern for data**: Components never import from `data/` directly. They call functions from `lib/adapters/mock-adapter.ts`. When real APIs arrive, add a new adapter — don't rewrite the mock.
- **HUD overlay pattern**: `HUD.tsx` is `pointer-events-none` over the full viewport. Interactive children use `pointer-events-auto`. This lets mouse events pass through to the Cesium canvas everywhere except UI controls.
- **Zustand-only state management**: No React Context, no Redux, no URL state. All shared state flows through `useAppStore`.
- **Free imagery only**: ESRI Dark Gray Canvas basemap via `UrlTemplateImageryProvider`. No Cesium Ion.

## Adding New Entity Layers (Recipe)

When adding a new entity type (e.g. cables, EEZ boundaries, conflict events):

1. **`lib/adapters/types.ts`** — Define the interface and add the type to `SelectedEntityType`.
2. **`data/{entity}.json`** — Add the dataset (or a script in `scripts/` to generate it).
3. **`lib/adapters/mock-adapter.ts`** — Add `get{Entity}()` and `get{Entity}ById()` functions.
4. **`store/useAppStore.ts`** — Add a layer toggle key to `LayerState` and a branch to `SelectedEntity`.
5. **`components/cesium/CesiumViewer.tsx`** — Create a new `CustomDataSource`, add entities with the `{type}:{id}` pattern, register in `entityMap`, subscribe to layer visibility.
6. **`components/ui/IntelligencePanel.tsx`** — Add a `{Entity}Detail` component and wire it into the selection switch.
7. **`components/ui/LayerToggleBar.tsx`** — Add an entry to `LAYER_CONFIG`.
